Introduction

Pro Max Matrimony, developed by Narjis Infotech, is a comprehensive matrimonial platform designed to simplify matchmaking, member management, communication, and complete platform administration. It provides powerful tools for members, staff, franchises, and administrators to manage the entire matrimonial ecosystem from a centralized platform.

Key Features

  • Easy Registration
    Simple and user-friendly registration process to create and manage member profiles.
  • Multiple Search
    Advanced search options with multiple filters to help members find suitable profiles efficiently.
  • Personalized Matchmaking
    Matchmaking based on member preferences, personal details, interests, and partner requirements.
  • Profile Management
    Complete management of member profiles, personal information, family details, preferences, photos, and profile status.
  • Membership Plan Management
    Create and manage membership plans, features, access permissions, validity, and plan-based member benefits.
  • Interest Management
    Manage sending, receiving, accepting, declining, and tracking member interests.
  • Notification Management
    Manage important notifications and updates for members, staff, and other users.
  • Secure Platform
    Secure management of member information with controlled access, permissions, and privacy settings.
  • Voice & Video Calling
    Enable members to communicate through integrated voice and video calling features.
  • App Feature Enable/Disable
    Control individual application features by enabling or disabling them according to business requirements.
  • Website Appearance Management
    Manage website appearance, content, banners, sections, and other visual elements from the administration panel.
  • App Appearance Management
    Manage application appearance and configurable app elements to maintain a consistent user experience.
  • Affiliate Marketing
    Manage affiliate partners, referrals, commissions, and affiliate-based member acquisition.
  • Staff Module
    Manage staff members, responsibilities, attendance, activities, and staff-related operations.
  • Franchise Module
    Manage franchise operations, franchise members, sales activities, and franchise-related reporting.
  • Member Field Enable/Disable
    Control which member profile fields are available or required across the platform.
  • Language Master
    Manage multiple languages and language-related content to support a multilingual matrimonial platform.

Match Making

The Matchmaking section provides two methods for finding suitable matrimonial matches:

It reduces manual effort by allowing administrators to configure matching rules, schedule match delivery, and select the preferred communication method.
    • Match Send Date – Allows the administrator to specify the date on which matches should be processed and sent to users.
    • Send Total Match to User – Defines the number of matching profiles to be sent to each user.

    • Match Criteria – Allows administrators to select multiple matching criteria, including Marital Status, Age, Height, Mother Tongue, Religion, Caste, Country, and Education.
    • Match Sending Mode – Allows administrators to choose the preferred notification method: Email, SMS, or Both.
    • Submit – Starts/saves the configured auto-match process based on the selected criteria and settings.
    • Recent Auto Match Scheduler History - Displays recent automated matchmaking activities, including date, sending mode, status, total members, matches sent, progress, start/completion time, and complete history access.

Chat/Message Flow

Chat Request

  • When User 1 sends the first message to User 2, the message should not be delivered immediately.
  • Instead, User 2 should receive a Chat Request with two options:

Accept

Reject

  • Until User 2 accepts the request, User 1's message should remain hidden.
  • If User 2 accepts the request:
    • The pending message(s) become visible.
    • Both users can continue chatting normally.
  • If User 2 rejects the request:
    • The chat request is declined.
    • No messages are delivered.
    • User 1 cannot continue the conversation unless a new chat request is allowed by the system.

Chat Blocking

  • Users can block another user only within the Chat module.
  • Chat blocking does not affect profile visibility or other features.
  • If User 1 blocks User 2 in chat:
    • User 2 can still send messages.
    • However, those messages will not be delivered to User 1.
    • User 1 will no longer receive any messages from User 2.
  • The block applies only to chat communication.

Message Status

Each message should display its delivery status.

Read

When the recipient opens and views the message, update the status to a double blue tick (✓✓).

Chat Flow

The Chat feature allows members to communicate with other members based on the Chat permission and limits defined in their Membership Plan. Users with an eligible membership plan can initiate a conversation by sending a Chat Request.

Chat Request

  • The Chat Request option is available through a dedicated Chat Request icon/button on the member profile.
  • When User 1 clicks the Chat Request button, a chat request is sent to User 2.
  • User 2 receives the Chat Request through a notification and it is also displayed in the Chat History section.
  • The initial message remains hidden from User 2 until the Chat Request is accepted.
  • User 2 can Accept or Reject the Chat Request.
  • Chat access is available only when permitted by the user's Membership Plan.

Accept Chat Request

  • Until User 2 accepts the Chat Request, User 1 cannot send or continue sending messages to User 2.
  • Once User 2 accepts the request, the chat conversation is activated for both users.
  • Both users can then continue chatting according to the Membership Plan.

Reject Chat Request

  • When User 2 rejects the request, the Chat Request is declined.
  • User 1 cannot send messages or continue the conversation with User 2 after the request is rejected.

Chat Blocking

  • Users can block another user only within the Chat module.
  • Chat blocking does not affect profile visibility or other features.
  • If User 1 blocks User 2 in chat:
    • User 2 can still send messages.
    • However, those messages will not be delivered to User 1.
    • User 1 will no longer receive any messages from User 2.
  • The block applies only to chat communication

Message Status

Each message should display its delivery status.

Message Sent

When a message is successfully sent from the sender's device, display a single black tick (✓).

Read Message

When the recipient opens and views the message, update the status to a double blue tick (✓✓).
